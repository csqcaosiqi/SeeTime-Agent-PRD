# SeeTime Agent — 城市治理版 产品设计文档

> **版本：** v1.2
> **最后更新：** 2026-03-25
> **状态：** 实现中（MVP 前端已完成框架，UI 全面重构进行中）

---

## 一、产品定位

SeeTime Agent 是一款**面向城市指挥调度员**的 Human-in-the-Loop AI 智能体平台，通过视频监控画面的智能分析，辅助城市治理场景中的巡查、异常识别、派单和报告生成。

**核心价值：**
- AI 自动扫描 + 人工复核，减少漏报和误报
- 步骤化任务流程，每步需操作员确认才推进
- 多任务并行，一个对话中可包含多个智能体任务
- 完整的从发现 → 派单 → 报告的全链路

**目标用户：** 城市指挥中心调度员（单一角色，命令中心操作员）

## 二、产品架构

### 2.1 三层智能体架构

```
用户输入
    ↓
Major-Agent（意图识别 + 路由）
    ↓
See 智能体（任务编排层，对应业务场景）
├── 市容环卫 See智能体
├── 城市异常事件 See智能体
├── 车辆违停 See智能体
└── 统计报告 See智能体
    ↓
Sub-Agent（步骤执行层，6个通用子智能体）
├── 查询范围确定
├── 异常查找
├── 异常结果
├── 智能派单
├── 数据检索
└── 报告生成
    ↓
Agent-Skill（原子能力层，17个 Skill）
```

### 2.2 四个 See 智能体

| 智能体 | 步骤序列 | 核心场景 |
|--------|----------|----------|
| 市容环卫 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | 垃圾堆放、占道经营 |
| 城市异常事件 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | 游商小贩、店外经营、非机动车乱停 |
| 车辆违停 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | 违章停车 |
| 统计报告 | 查询范围确定→数据检索→报告生成 | 周期性统计分析 |

**步骤编排**：由后端配置，支持动态调整（当前 MVP 前端硬编码）

### 2.3 视觉检测两条路径
- **特征-分割识别**：用于识别目标物体（垃圾、违停车辆等），基于 YOLOv8（DEMO 用开源，生产用自研）
- **连续帧时序判断**：用于识别行为（游商摆摊等），需要多帧分析

## 三、交互设计规范（v1.2 全面更新）

### 3.1 布局结构

```
┌──────────────┬───────────────────┬──────────────────────────┐
│  左侧边栏    │    Chat 区        │    Canvas 区（多模态画板）│
│  240px 固定  │  420px（有任务时）│   flex-1（任务命中后弹出）│
│  深色        │  flex-1（无任务时）│   初始隐藏，平行弹出     │
└──────────────┴───────────────────┴──────────────────────────┘
```

**Canvas 弹出规则：**
- 任务创建前：Canvas 区隐藏，Chat 区占满内容区
- 任务命中后：Canvas 从右侧滑入（ease-out，250ms），Chat 压缩为 420px 固定宽
- Canvas 弹出后为主显示区，但用户仍可在 Chat 区交互
- Canvas 收起：点击"收起画板"按钮，Canvas 隐藏，Chat 恢复全宽
- 任务进行中时，Chat 区右侧有动态脉冲按钮，点击可重新展开 Canvas

### 3.2 左侧边栏

```
┌────────────────────────┐
│ [●] SeeTime Agent  [<] │  ← Logo + 折叠按钮
├────────────────────────┤
│ [+ 新建对话]           │  ← 主操作按钮
├────────────────────────┤
│ SEE 智能体             │  ← Section label
│ [市容环卫]             │
│ [城市异常事件]         │  ← 4个快捷入口按钮
│ [车辆违停]             │
│ [统计报告]             │
├────────────────────────┤
│ [对话列表] [任务列表]  │  ← Tabs
│ 🔍 搜索对话...         │
│                        │
│ 中山路市容巡查     任务│
│ 城南区异常事件排查 任务│
│ ...                    │
├────────────────────────┤
│ [头像] 张** 指挥调度员 │  ← 用户信息
└────────────────────────┘
```

**对话与任务的关系：**
- 一个对话中可包含多个任务
- 任务是从对话中提取出来的，在"任务列表" Tab 中单独呈现
- 对话列表每条带"任务"标签（如果该对话包含任务）

### 3.3 Chat 区 AI 输出结构

每一轮 AI 交互输出由以下部分组成（流程图）：

```
用户 Query                    ← 右对齐气泡，靛蓝浅色背景

● {任务名称}-{步骤名称}
  ┌─────────────────────────────────────────────┐
  │ Thinking（默认收起）  ▼ 点击查看推理过程    │  ← 可折叠卡片
  │ AI 拆解要执行的动作，思考完成后自动收起     │
  └─────────────────────────────────────────────┘

  [任务卡片：紫色背景]
  @{智能体名称} 创建 "{任务名称}"              ← 任务卡片（#1C183A）
  进入 {步骤名称}              {任务文档名} ↗

  执行进度 ({技能名称})  ████████████  100%    ← 技能进度条

  {执行结论文本}                               ← 自然语言结论
```

**组件规范：**
- Thinking 卡片：bg `#0F0F1A`，默认折叠，点击展开，脑图图标 + "Thinking" 标签
- 任务卡片：bg `#1C183A`，border `rgba(99,102,241,0.3)`，显示智能体/任务/步骤/文档链接
- 技能进度：靛蓝渐变进度条，技能名称左对齐
- 结论文本：`#CBD5E1`，1.6 行高

### 3.4 Canvas 区（多模态画板）

```
┌─────────────────────────────────────────────────────┐
│ {任务名称}                          [← 收起画板]    │  ← Header
├─────────────────────────────────────────────────────┤
│ 步骤1-查询范围确定 ✓ > 步骤2-异常查找 ▼ > ...      │  ← 步骤条
├─────────────────────────────────────────────────────┤
│                                                     │
│              当前步骤的交互内容                     │  ← 步骤视图
│                                                     │
├─────────────────────────────────────────────────────┤
│                              [执行下一步动作 →]     │  ← 底部操作
└─────────────────────────────────────────────────────┘
```

**步骤条交互：**
- 线性水平步骤条，已完成 ✓ 绿色，当前高亮靛蓝，未来灰色
- 每个步骤旁有 `∨` 箭头，点击展开显示**该步骤的定义说明**（这一步的目标、输入、输出是什么）
- 支持点击已完成步骤回跳（back-jump）
- 回跳后修改输出 → 检测到 output hash 变化 → 级联清空后续步骤

**步骤视图对应关系：**
| 步骤 | 视图 | 主要内容 |
|------|------|----------|
| 查询范围确定 | ScopeView | 地图 + 摄像头列表（或时间/类型过滤器） |
| 异常查找 | ScanningView | 扫描动画 → 完成提示 |
| 异常结果 | ResultView | 检测卡片网格，支持删除/修改分类 |
| 智能派单 | DispatchView | 派单表格 + 接收方选择 |
| 数据检索 | SearchView（=ScanningView）| 数据检索进度 |
| 报告生成 | ReportView | 图表 + 明细表 + 导出 |

**"执行下一步动作"按钮：**
- 位置：Canvas 右下角
- 状态：当前步骤为 `waiting_user` 或 `completed` 时可点击
- 最后一步变为"完成任务"
- 点击后：当前步骤标记 `completed`，下一步进入 `executing`

**Canvas 收起动态按钮：**
- 当 Canvas 收起且任务进行中时，Chat 区右侧边缘出现带脉冲动画的浮动按钮
- 点击可重新展开 Canvas
- 脉冲动画：`box-shadow` 呼吸效果，2s 循环

### 3.5 步骤流转规则

1. **强制推进**：必须手动点击"执行下一步动作"
2. **自由回跳**：可点击已完成的步骤回到任意历史步骤
3. **级联清空**：若回跳后修改了该步骤的输出（output hash 变化），则后续所有步骤自动清空并重新执行
4. **输出保存**：每个步骤的输出实时保存到 Zustand store

## 四、视觉设计规范（v1.2）

### 4.1 色彩系统（深色 AI 主题）

| Token | 色值 | 用途 |
|-------|------|------|
| `--color-bg-base` | `#08080F` | 主背景 |
| `--color-bg-sidebar` | `#0C0C16` | 左侧边栏 |
| `--color-bg-elevated` | `#12121E` | 卡片、面板 |

| `--color-bg-thinking` | `#0F0F1A` | Thinking 卡片 |
| `--color-bg-task-card` | `#1C183A` | 任务卡片（紫色调） |
| `--color-primary` | `#6366F1` | 主色（靛蓝）|
| `--color-primary-light` | `#818CF8` | 主色浅 |
| `--color-primary-dim` | `rgba(99,102,241,0.15)` | 靛蓝背景色 |
| `--color-text-primary` | `#F1F5F9` | 主文本 |
| `--color-text-secondary` | `#94A3B8` | 次要文本 |

| `--color-border` | `rgba(255,255,255,0.07)` | 边框 |

### 4.2 字体

- **主字体**：Plus Jakarta Sans（Google Fonts）
- **字号**：11px（极小）/ 12px（辅助）/ 13px（正文）/ 14px（标准）/ 22px（标题）
- **行高**：正文 1.5-1.6，代码/日志 1.7

### 4.3 动效规范

| 场景 | 参数 |
|------|------|
| Canvas 滑入 | `translateX(24px) → 0`，`opacity 0→1`，`250ms ease-out` |
| Canvas 折叠按钮脉冲 | `box-shadow` 呼吸，`2s infinite`，仅任务进行时 |
| 卡片 hover | `background` 变化，`150ms ease` |
| 步骤切换 | 内容区淡入，`200ms` |
| Thinking 展开 | `max-height` 展开，`200ms ease-out` |
| 进度条填充 | `width` 变化，`500ms ease` |

## 六、非功能性要求

- 单任务完整流程（5步）不超过 10 分钟
- 前端页面切换响应 < 200ms
- Canvas 滑入动画流畅（60fps）
- 支持多任务并行（每个 See 智能体任务独立实例）
- 单一操作员角色，无权限分级（MVP 阶段）
