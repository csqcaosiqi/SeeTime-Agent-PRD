# SeeTime Agent — 城市治理版 产品设计文档

> **版本：** v1.3
> **最后更新：** 2026-03-25
> **状态：** 实现中（MVP 前端已完成框架，UI 全面重构进行中）

---

## 一、产品定位

SeeTime Agent 是一款**面向城市指挥调度员**的 Human-in-the-Loop AI 智能体平台，通过视频监控画面的智能分析，辅助城市治理场景中的巡查、异常识别、派单和报告生成。

**核心价值：**
- AI 自动扫描 + 人工复核，减少漏报和误报
- 步骤化任务流程，每步需操作员确认才推进
- 多任务并行，一个对话中可包含多个智能体任务
- 完整的从发现 → 派单 → 报告的全链路

**目标用户：** 城市指挥中心调度员（单一角色，命令中心操作员）

## 二、产品架构

### 2.1 三层智能体架构

```
用户输入
    ↓
Major-Agent（意图识别 + 路由）
    ↓
See 智能体（任务编排层，对应业务场景）
├── 市容环卫 See智能体
├── 城市异常事件 See智能体
├── 车辆违停 See智能体
└── 统计报告 See智能体
    ↓
Sub-Agent（步骤执行层，6个通用子智能体）
├── 查询范围确定
├── 异常查找
├── 异常结果
├── 智能派单
├── 数据检索
└── 报告生成
    ↓
Agent-Skill（原子能力层，17个 Skill）
```

### 2.2 四个 See 智能体

| 智能体 | 步骤序列 | 核心场景 | 检测路径 |
|--------|----------|----------|----------|
| 市容环卫 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | **垃圾相关**：垃圾堆放、垃圾桶满溢、暴露垃圾 | 特征-分割识别 |
| 城市异常事件 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | **非垃圾城市异常**：游商小贩、占道经营、店外经营、非机动车乱停 | 连续帧时序判断 |
| 车辆违停 | 查询范围确定→异常查找→异常结果→智能派单→报告生成 | 违章停车 | 特征-分割识别 |
| 统计报告 | 查询范围确定→数据检索→报告生成 | 周期性统计分析 | 数据查询（无视觉检测）|

**步骤编排**：由后端配置，支持动态调整（当前 MVP 前端硬编码）

### 2.3 视觉检测两条路径

| 路径 | 适用场景 | 技术说明 |
|------|----------|----------|
| **特征-分割识别** | 识别目标物体：垃圾堆放、违停车辆、垃圾桶满溢 | YOLOv8（DEMO 开源，生产自研）|
| **连续帧时序判断** | 识别行为：游商摆摊、店外经营、占道经营 | 多帧分析 + 时序推理 |

智能体与路径的映射见 §2.2 表格"检测路径"列。

### 2.4 六个 Sub-Agent 定义（数据契约）

#### 4.1 查询范围确定 Sub-Agent

| 项目 | 说明 |
|------|------|
| **职责** | 解析用户意图，确定任务类型、扫描范围，映射到具体摄像头列表，供用户确认调整 |
| **输入** | 用户自然语言指令 + See 智能体传入的任务类型 |
| **输出** | 任务类型与描述、地理围栏、摄像头列表（含位置和覆盖范围）、地图渲染数据 |
| **决策逻辑** | 模糊地名 → 调用地址解析；指定路段 → 调用摄像头匹配；说"全城" → 加载全量摄像头按区划分组 |
| **可调用 Skill** | 地址解析、摄像头匹配、地图渲染 |
| **Canvas 呈现** | 地图（标注摄像头位置+覆盖范围）+ 摄像头列表（支持增删）|

#### 4.2 异常查找 Sub-Agent

| 项目 | 说明 |
|------|------|
| **职责** | 按摄像头列表逐一执行视觉检测，发现目标异常 |
| **输入** | 摄像头列表 + 任务类型（决定检测什么）|
| **输出** | 异常事件集合（每条含：摄像头 ID、截图、检测框坐标、初步分类、置信度、时间戳）|
| **决策逻辑** | 目标物检测（垃圾/违停/乱停）→ 特征-分割识别 Skill；行为检测（店外经营/游商小贩）→ 连续帧时序判断 Skill |
| **可调用 Skill** | 特征-分割识别、连续帧时序判断 |
| **Canvas 呈现** | 扫描进度动画（Chat 区展示技能执行进度条），Canvas 区无交互内容 |

#### 4.3 异常结果 Sub-Agent

| 项目 | 说明 |
|------|------|
| **职责** | 将检测结果结构化，供人工复核，支持删除误报和修改分类 |
| **输入** | 异常事件集合（来自异常查找 Sub-Agent）|
| **输出** | 用户确认后的异常事件列表（已去除误报，分类已校正）|
| **决策逻辑** | 默认全选，用户主动删除误报；支持修改事件子类型 |
| **可调用 Skill** | 无（纯人机交互步骤）|
| **Canvas 呈现** | 检测结果卡片网格（截图+检测框+地址+时间+子类型标签，支持删除/修改）|

#### 4.4 智能派单 Sub-Agent

| 项目 | 说明 |
|------|------|
| **职责** | 根据事件位置和类型，自动匹配责任单位和接收人，生成派单记录 |
| **输入** | 已确认的异常事件列表 + 派单映射规则（后端维护：区域×事件类型 → 接收人）|
| **输出** | 派单记录列表（每条含：事件 ID、接收单位、接收人、派单时间）|
| **决策逻辑** | 按区域+事件类型查询映射表，自动匹配接收人；用户可手动覆盖 |
| **可调用 Skill** | 派单规则查询、派单记录写入 |
| **Canvas 呈现** | 派单表格（截图缩略图 / 事件类型 / 发生地址 / 接收单位 / 接收人下拉 / 操作）|

#### 4.5 数据检索 Sub-Agent（统计报告智能体专用）

| 项目 | 说明 |
|------|------|
| **职责** | 从历史数据库检索指定时间范围和事件类型的数据 |
| **输入** | 时间范围、事件类型过滤条件（来自用户在 ScopeView 的设置）|
| **输出** | 事件聚合数据（按类型/区域/时间分组的统计结果）|
| **决策逻辑** | 按过滤条件构造查询；时间范围跨度过大时提示用户缩减 |
| **可调用 Skill** | 数据聚合查询 |
| **Canvas 呈现** | 检索进度（复用 ScanningView 样式）|

#### 4.6 报告生成 Sub-Agent

| 项目 | 说明 |
|------|------|
| **职责** | 基于任务数据或历史检索数据，生成结构化报告 |
| **输入** | 已确认事件列表 + 派单记录（巡查任务），或聚合数据（统计报告）|
| **输出** | 报告结构化数据（图表数据 + 明细表）+ PDF 导出文件 |
| **决策逻辑** | 根据数据类型选择图表；事件数为0时提示无内容 |
| **可调用 Skill** | 报告模板渲染、PDF 导出 |
| **Canvas 呈现** | 见 §3.4 ReportView 定义 |

## 三、交互设计规范（v1.2 全面更新）

### 3.1 布局结构

```
┌──────────────┬───────────────────┬──────────────────────────┐
│  左侧边栏    │    Chat 区        │    Canvas 区（多模态画板）│
│  240px 固定  │  420px（有任务时）│   flex-1（任务命中后弹出）│
│  深色        │  flex-1（无任务时）│   初始隐藏，平行弹出     │
└──────────────┴───────────────────┴──────────────────────────┘
```

**Canvas 弹出规则：**
- 任务创建前：Canvas 区隐藏，Chat 区占满内容区
- 任务命中后：Canvas 从右侧滑入（ease-out，250ms），Chat 压缩为 420px 固定宽
- Canvas 弹出后为主显示区，但用户仍可在 Chat 区交互
- Canvas 收起：点击"收起画板"按钮，Canvas 隐藏，Chat 恢复全宽
- 任务进行中时，Chat 区右侧有动态脉冲按钮，点击可重新展开 Canvas

### 3.2 左侧边栏

```
┌────────────────────────┐
│ [●] SeeTime Agent  [<] │  ← Logo + 折叠按钮
├────────────────────────┤
│ [+ 新建对话]           │  ← 主操作按钮
├────────────────────────┤
│ SEE 智能体             │  ← Section label
│ [市容环卫]             │
│ [城市异常事件]         │  ← 4个快捷入口按钮
│ [车辆违停]             │
│ [统计报告]             │
├────────────────────────┤
│ [对话列表] [任务列表]  │  ← Tabs
│ 🔍 搜索对话...         │
│                        │
│ 中山路市容巡查     任务│
│ 城南区异常事件排查 任务│
│ ...                    │
├────────────────────────┤
│ [头像] 张** 指挥调度员 │  ← 用户信息
└────────────────────────┘
```

**对话与任务的关系：**
- 一个对话中可包含多个任务
- 任务是从对话中提取出来的，在"任务列表" Tab 中单独呈现
- 对话列表每条带"任务"标签（如果该对话包含任务）

### 3.3 Chat 区 AI 输出结构

每一轮 AI 交互输出由以下部分组成（流程图）：

```
用户 Query                    ← 右对齐气泡，靛蓝浅色背景

● {任务名称}-{步骤名称}
  ┌─────────────────────────────────────────────┐
  │ Thinking（默认收起）  ▼ 点击查看推理过程    │  ← 可折叠卡片
  │ AI 拆解要执行的动作，思考完成后自动收起     │
  └─────────────────────────────────────────────┘

  [任务卡片：紫色背景]
  @{智能体名称} 创建 "{任务名称}"              ← 任务卡片（#1C183A）
  进入 {步骤名称}              {任务文档名} ↗

  执行进度 ({技能名称})  ████████████  100%    ← 技能进度条

  {执行结论文本}                               ← 自然语言结论
```

**组件规范：**
- Thinking 卡片：bg `#0F0F1A`，默认折叠，点击展开，脑图图标 + "Thinking" 标签
- 任务卡片：bg `#1C183A`，border `rgba(99,102,241,0.3)`，显示智能体/任务/步骤/文档链接
- 技能进度：靛蓝渐变进度条，技能名称左对齐
- 结论文本：`#CBD5E1`，1.6 行高

### 3.4 Canvas 区（多模态画板）

```
┌─────────────────────────────────────────────────────┐
│ {任务名称}                          [← 收起画板]    │  ← Header
├─────────────────────────────────────────────────────┤
│ 步骤1-查询范围确定 ✓ > 步骤2-异常查找 ▼ > ...      │  ← 步骤条
├─────────────────────────────────────────────────────┤
│                                                     │
│              当前步骤的交互内容                     │  ← 步骤视图
│                                                     │
├─────────────────────────────────────────────────────┤
│                              [执行下一步动作 →]     │  ← 底部操作
└─────────────────────────────────────────────────────┘
```

**步骤条交互：**
- 线性水平步骤条，已完成 ✓ 绿色，当前高亮靛蓝，未来灰色
- 每个步骤旁有 `∨` 箭头，点击展开显示**该步骤的纯文本定义说明**（格式见下）
- 支持点击已完成步骤回跳（back-jump）
- 回跳后修改输出 → 检测到 output hash 变化 → 级联清空后续步骤

**步骤展开文案（Canvas 步骤 `∨` 展开内容）：**

| 步骤 | 展开说明文案 |
|------|-------------|
| 查询范围确定 | 根据你描述的区域或路段，确定本次任务覆盖的摄像头列表和地理范围。你可以在地图上增删摄像头，确认后作为后续扫描的输入范围。 |
| 异常查找 | AI 逐一分析所选摄像头的画面，根据任务类型识别目标异常（垃圾/违停/异常行为等）。此步骤自动执行，无需操作，请等待执行完成。 |
| 异常结果 | 展示所有 AI 识别出的疑似异常，默认全部选中。你可以删除误报、修改事件分类，确认后进入派单环节。 |
| 智能派单 | 根据异常位置和事件类型，自动匹配责任单位和处理人员。你可以手动调整接收方，确认后生成正式派单记录。 |
| 数据检索 | 从历史数据库中检索符合筛选条件的事件数据，用于生成统计报告。此步骤自动执行，无需操作。 |
| 报告生成 | 基于本次任务数据或历史检索结果，自动生成包含事件分布、派单情况和趋势分析的完整报告，支持导出 PDF。 |

**步骤视图对应关系：**
| 步骤 | 视图 | 主要内容 |
|------|------|----------|
| 查询范围确定 | ScopeView | 地图 + 摄像头列表（或时间/类型过滤器） |
| 异常查找 | ScanningView | 扫描动画 → 完成提示 |
| 异常结果 | ResultView | 检测卡片网格，支持删除/修改分类 |
| 智能派单 | DispatchView | 派单表格 + 接收方选择 |
| 数据检索 | SearchView | 数据检索进度（复用 ScanningView 组件样式，语义独立）|
| 报告生成 | ReportView | 图表 + 明细表 + 导出 |

**"执行下一步动作"按钮：**
- 位置：Canvas 右下角
- 状态：当前步骤为 `waiting_user` 或 `completed` 时可点击
- 最后一步变为"完成任务"
- 点击后：当前步骤标记 `completed`，下一步进入 `executing`

**Canvas 收起动态按钮：**
- 当 Canvas 收起且任务进行中时，Chat 区右侧边缘出现带脉冲动画的浮动按钮
- 点击可重新展开 Canvas
- 脉冲动画：`box-shadow` 呼吸效果，2s 循环

### 3.5 步骤流转规则

1. **强制推进**：必须手动点击"执行下一步动作"
2. **自由回跳**：可点击已完成的步骤回到任意历史步骤
3. **级联清空**：若回跳后修改了该步骤的输出（output hash 变化），则后续所有步骤自动清空并重新执行
4. **输出保存**：每个步骤的输出实时保存到 Zustand store
5. **回跳时 Chat 区联动**：用户点击回跳某步骤时，Chat 区自动输出一条新的 AI 消息，结构为：
   - Thinking 卡片（折叠）：说明为什么回跳、上下文变化
   - 任务卡片（紫色）：`@{智能体} 进入步骤{X}-{步骤名}`
   - 执行结论：`已进入步骤X，请在画板区进行操作`

## 六、非功能性要求

- 单任务完整流程（5步）不超过 10 分钟
- 前端页面切换响应 < 200ms
- Canvas 滑入动画流畅（60fps）
- 支持多任务并行（每个 See 智能体任务独立实例）
- 单一操作员角色，无权限分级（MVP 阶段）
