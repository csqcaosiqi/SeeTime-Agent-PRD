# 产品研发版本流转机制

> 版本：v1.0 · 更新时间：2026-05-25

---

## 一、核心概念

| 概念 | 定义 |
|------|------|
| **迭代** | 一组版本的集合，周期灵活，由业务需求驱动创建 |
| **版本** | 某个产品的一次交付单元，独立编号 |

---

## 二、版本号规则

采用语义化版本：`主版本.次版本.修订号`

- **主版本**：重大功能变更、架构升级、不兼容变更
- **次版本**：新功能增加、向下兼容
- **修订号**：Bug 修复、小优化

---

## 三、版本信息卡片

| 字段 | 填写方 | 时机 |
|------|--------|------|
| 迭代归属 | 产品 | 规划时 |
| 版本号 | 产品 | 规划时 |
| 版本说明 | 产品 | 规划时 |
| 产品主R | 产品 | 规划时 |
| 技术主R | 研发 | PRD评审会 |
| 预期开始时间 | 产品 | 规划时 |
| 预期结束时间 | 产品 | 规划时 |

---

## 四、流转节点

```
产品创建版本 → PRD评审（确定技术主R）→ 研发排期 → 开发 → 测试 → 上线
```

---

## 五、突发需求处理

1. **新建迭代**，装入紧急版本
2. **调整现有迭代的优先级**，必要时暂缓低优先级版本

---

## 六、协作规范

### 1. PRD变更管理

- 需求评审会后如需修改PRD，必须更新文档版本号
- 变更时需明确说明需求变化点（改了什么、为什么改）

### 2. 评审参与方

- 需求评审会必须带上算法同学

### 3. 数据接入周知

- 新的城市数据接入时，产品需主动周知算法侧

### 4. 问答场景示例

- PRD中涉及自然语言问答功能时，需提供用户问答的场景示例，便于研发测试
