# Part 1 — 产品视角

## 1. 产品定位与价值主张

### 产品名称

SeeTime Agent

### 一句话定义

面向城市治理场景的人机协作视频智能体平台，将存量监控摄像头转化为可理解、可执行、可闭环的城市治理数字劳动力。

### 核心价值主张

| 维度 | 传统方案（人工巡查/传统AI） | SeeTime Agent |
|------|--------------------------|---------------|
| 发现能力 | 靠人眼盯屏或固定规则告警，漏检率高 | AI 全城扫描，按需检测，漏检率极低 |
| 决策模式 | 全自动（误报泛滥）或全人工（效率极低） | 人机协作——AI 筛选发现，人工一键拍板 |
| 执行闭环 | 发现归发现，派单归派单，系统割裂 | 发现→审核→派单→报告，一条链路闭环 |
| 算力成本 | 全量实时分析，GPU 成本高昂 | 按需扫描，低频轮巡，算力克制 |
| 扩展性 | 每种场景单独开发一套系统 | 通用 Sub-Agent 积木式复用，新场景只需编排 |

### 目标客户

城市治理指挥中心（城管局、综合执法局、一网统管平台）

### MVP 用户角色

指挥中心操作员——负责发起巡查任务、审核 AI 检测结果、确认派单、查阅报告的核心决策者。

### MVP 范围

- 仅支持用户触发的主动搜索模式（定时轮巡列为后续版本）
- 4 个 See 智能体：市容环卫、城市异常事件、车辆违停、统计报告
- 单用户角色（指挥中心操作员）
- 支持多任务并行
- 任务发起方式：自然语言 + 导航区选择，两种并存

## 2. 四个 See 智能体：用户故事与任务流程

### 通用交互规则

以下规则适用于所有 See 智能体：

1. **强制人工推进**：每一步完成后，用户必须手动点击【下一步】才能进入后续步骤，不自动跳转。
2. **回跳自由**：用户可点击任意已完成的步骤，跳转回该步骤与对应 Sub-Agent 交互调整。
3. **变更级联清理**：用户在回跳步骤中操作完毕点击【下一步】时，系统对比该 Sub-Agent 的输出与之前的输出。输出无变化则恢复后续已有结果；输出有变化则清空该步骤之后所有步骤的内容，从下一步开始重新执行。
4. **批量审核默认通过**：人工审核环节，未操作的条目默认通过，用户只需剔除误检。

### 2.1 市容环卫智能体（Clean Guardian）

**用户故事：**

> 作为指挥中心操作员，我希望 AI 按我指定的区域扫描摄像头画面，自动发现垃圾堆积/滞留问题，经我逐步审核确认后，自动派单给对应网格员，并生成检测报告。

**典型指令：**

- "扫描中山路的垃圾情况"
- "扫描城南片区所有主干道的环卫情况"

**任务流程（5 步）：**

#### 步骤 1：查询范围确定

| 项目 | 说明 |
|------|------|
| Chat 区 | 输出本次任务类型和任务描述（如"市容环卫-垃圾检测，范围：中山路"） |
| Canvas 区 | 渲染地图，标注该范围内所有摄像头位置及覆盖范围；右侧展示摄像头列表 |
| 用户操作 | 在地图/列表上增删摄像头，调整实际扫描范围 |
| 步骤目标 | 让用户明确"在什么范围做什么事"，确认后点击【下一步】 |

#### 步骤 2：异常查找

| 项目 | 说明 |
|------|------|
| Chat 区 | 实时显示执行进度（如"正在扫描第 12/52 个摄像头...已发现 3 处疑似异常"） |
| Canvas 区 | 无内容展示（后台执行中） |
| 步骤目标 | 执行视觉检测（特征-分割识别路径），扫描完成后自动提示用户点击【下一步】 |

#### 步骤 3：异常结果

| 项目 | 说明 |
|------|------|
| Canvas 区 | 批量平铺结果卡片，每张卡片包含：摄像头截图 + 检测框标注 + 街道名称 + 时间戳 + 细分类标签（生活垃圾、垃圾桶满溢、建筑垃圾等） |
| 用户操作 | 快速删除误检卡片；修改细分类标签 |
| 默认逻辑 | 未操作的卡片默认通过 |
| 步骤目标 | 人工审核确认结果集，调整完毕后点击【下一步】 |

#### 步骤 4：智能派单

| 项目 | 说明 |
|------|------|
| Canvas 区 | 展示派单结果列表：每个异常事件 → 自动匹配的接收方（网格员/处理单位） |
| 用户操作 | 支持手动调整"异常事件 <-> 接收方"的对应关系 |
| 步骤目标 | 确认派单分配，调整完毕后点击【下一步】 |

#### 步骤 5：报告生成

| 项目 | 说明 |
|------|------|
| Canvas 区 | 渲染完整报告，包含三个视角： |
| | **事件视角**：异常类型分布（饼图/柱状图）+ 空间分布（地图热力图） |
| | **派单视角**：哪个地点的哪个事件派给了哪个接收方（明细表） |
| | **接收方视角**：各接收方管辖范围内的问题数量排名 |
| 用户操作 | 查阅报告，可导出 |

### 2.2 城市异常事件智能体（City Patrol）

**用户故事：**

> 作为指挥中心操作员，我希望指定要查找的异常事件类型和范围，AI 全城扫描后批量展示结果，经我审核后自动派单到对应处理单位。

**典型指令：**

- "查找建设路全线的店外经营情况"
- "全城扫描非机动车乱停和共享单车乱停"

**任务流程：同市容环卫（5 步），以下为关键差异：**

| 步骤 | 差异说明 |
|------|---------|
| 1. 查询范围确定 | 额外需要用户指定或确认**目标事件类型**（可多选：店外经营、游商小贩、非机动车乱停、共享单车乱停等），Chat 区输出任务描述需包含选定的事件类型列表 |
| 2. 异常查找 | 技术路径因事件类型而异：非机动车乱停/共享单车乱停 → 特征-分割识别；店外经营/游商小贩 → 连续帧+时序判断。Sub-Agent 内部自动路由，用户无感 |
| 3. 异常结果 | 细分类标签不同（店外经营、游商小贩、非机动车乱停、共享单车乱停等）；若用户选了多种事件类型，结果卡片支持按类型筛选 |
| 4. 智能派单 | 接收方可能因事件类型不同而不同（如非机动车乱停 → 交管队，店外经营 → 城管中队），映射表需支持事件类型维度 |
| 5. 报告生成 | 事件视角增加多类型对比维度（各类型事件数量对比、各类型空间分布对比） |

---

### 2.3 车辆违停智能体（Parking Watcher）

**用户故事：**

> 作为指挥中心操作员，我希望 AI 扫描指定范围内的机动车违停和占用便道行为，经我审核确认后派单给相关处理单位。

**典型指令：**

- "扫描人民路沿线的机动车违停"
- "查找城西片区所有占用便道的车辆"

**任务流程：同市容环卫（5 步），以下为关键差异：**

| 步骤 | 差异说明 |
|------|---------|
| 1. 查询范围确定 | 同市容环卫，无特殊差异 |
| 2. 异常查找 | 技术路径：特征-分割识别（识别车辆+判断是否在违停区域） |
| 3. 异常结果 | 卡片信息增加：车牌号（OCR 识别，可能为空/模糊）、违停类型细分（路边违停、占用便道、占用消防通道等） |
| 4. 智能派单 | 接收方通常为交管大队/城管中队，粒度可能按辖区划分 |
| 5. 报告生成 | 事件视角增加车牌维度（可识别的车牌列表、重复违停车辆统计） |

---

### 2.4 统计报告智能体（Data Reporter）

**用户故事：**

> 作为指挥中心操作员，我希望从历史数据中按条件提取事件记录，生成统计分析报告，用于复盘和汇报。

**典型指令：**

- "提取最近一周的违停数据，生成报告"
- "统计本月城南片区所有异常事件的类型分布"

**任务流程（3 步）：**

#### 步骤 1：查询范围确定

| 项目 | 说明 |
|------|------|
| Chat 区 | 输出查询条件摘要（时间范围 + 空间范围 + 事件类型筛选条件） |
| Canvas 区 | 渲染地图标注查询的空间范围；展示筛选条件面板 |
| 用户操作 | 调整时间范围、空间范围、事件类型筛选条件 |
| 步骤目标 | 确认"从什么范围提取什么数据"，点击【下一步】 |

#### 步骤 2：数据检索

| 项目 | 说明 |
|------|------|
| Chat 区 | 显示检索进度（如"正在检索...已匹配 328 条记录"） |
| Canvas 区 | 无内容展示 |
| 步骤目标 | 从历史数据库中按条件查询，完成后提示点击【下一步】 |

#### 步骤 3：报告生成

| 项目 | 说明 |
|------|------|
| Canvas 区 | 渲染统计报告，视角包括： |
| | **趋势视角**：时间轴上的事件数量变化趋势 |
| | **类型视角**：各异常类型分布对比 |
| | **空间视角**：地图热力图展示问题高发区域 |
| | **接收方视角**：各处理单位的派单量与处理情况 |
| 用户操作 | 查阅报告，可导出 |

# Part 2 — 系统视角

## 3. 三层架构总览

### 架构分层

```
用户交互层
  Chat 区 · Canvas 区 · Agent 导航区
      │
      │ 自然语言 / 导航选择
      ▼
Major-Agent（总调度）
  意图识别 → 选择 See 智能体 → 监控执行 → 汇总结果
      │
      │ 调度
      ▼
See 智能体层（任务编排）
  Clean Guardian · City Patrol · Parking Watcher · Data Reporter
  读取后端配置的步骤编排 → 按序调用 Sub-Agent
      │
      │ 按步骤调用
      ▼
Sub-Agent 层（步骤执行）
  查询范围确定 · 异常查找 · 异常结果 · 智能派单 · 数据检索 · 报告生成
  根据步骤目标 + 用户输入 → 自主选择 Skill 组合
      │
      │ 调用
      ▼
Agent-Skill 层（能力原子）
  地址解析 · 摄像头匹配 · 地图渲染 · 特征-分割识别
  连续帧时序判断 · OCR · 派单映射查询 · 报告模板渲染
  数据库检索 · 统计图表生成 · ...
```

### 各层职责边界

| 层级 | 职责 | 决策权 | 不做什么 |
|------|------|--------|---------|
| Major-Agent | 理解用户意图，选择合适的 See 智能体，管理多任务并行 | 选哪个 See 智能体 | 不参与具体步骤执行 |
| See 智能体 | 读取后端步骤配置，按序调度 Sub-Agent，管理步骤间的"下一步"流转 | 步骤顺序和流转控制 | 不决定步骤内部用哪些 Skill |
| Sub-Agent | 执行单个步骤，根据步骤目标+用户输入自主选择 Skill 组合 | 用哪些 Skill、怎么组合 | 不知道自己在哪个任务流程中 |
| Agent-Skill | 纯能力执行，接收参数返回结果 | 无决策权 | 不知道上下文 |

### 关键设计原则

1. **步骤编排后端可配置**：See 智能体的步骤序列从后端读取，新增/调整步骤无需改前端代码。
2. **Sub-Agent 通用复用**：同一个 Sub-Agent 服务于所有 See 智能体，通过步骤目标参数化。
3. **强制人工推进**：每步完成后等待用户点击【下一步】，See 智能体才调度下一个 Sub-Agent。
4. **回跳与级联清理**：用户可回跳至任意已完成步骤调整，若输出变化则清空后续步骤内容重新执行。

### 步骤流转控制

| 规则 | 说明 |
|------|------|
| 顺序推进 | 步骤按配置顺序执行，每步完成后用户点击【下一步】推进 |
| 回跳自由 | 用户可点击任意已完成的步骤，跳转回该步骤与对应 Sub-Agent 交互调整 |
| 变更检测 | 用户在回跳步骤中操作完毕点击【下一步】时，系统对比该 Sub-Agent 的输出与之前的输出 |
| 无变化 | 输出一致 → 直接恢复后续步骤的已有结果，用户可继续往下 |
| 有变化 | 输出不一致 → 清空该步骤之后所有步骤的内容，从下一步开始重新执行 |

## 4. 六个通用 Sub-Agent 定义

> 以下为初版基线定义，随实现推进可迭代调整。

### 4.1 查询范围确定 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 解析用户意图，确定任务类型、扫描范围，映射到具体摄像头列表，供用户确认调整 |
| 输入 | 用户自然语言指令 + See 智能体传入的任务类型 |
| 输出 | 任务类型与描述、地理围栏、摄像头列表（含位置和覆盖范围）、地图渲染数据 |
| 决策逻辑 | 根据用户输入判断：模糊地名 → 调用地址解析；指定具体路段 → 调用摄像头匹配；说"全城" → 加载全量摄像头并按区划分组 |
| 可调用 Skill | 地址解析、摄像头匹配、地图渲染 |
| Canvas 呈现 | 地图（标注摄像头位置+覆盖范围）+ 摄像头列表（支持增删） |

### 4.2 异常查找 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 按摄像头列表逐一执行视觉检测，发现目标异常 |
| 输入 | 摄像头列表 + 任务类型（决定检测什么） |
| 输出 | 异常事件集合（每条含：摄像头 ID、截图、检测框坐标、初步分类、置信度、时间戳） |
| 决策逻辑 | 根据任务类型自动路由技术路径：目标物检测（垃圾、违停、乱停）→ 特征-分割识别 Skill；行为检测（店外经营、游商小贩）→ 连续帧时序判断 Skill |
| 可调用 Skill | 特征-分割识别、连续帧时序判断、摄像头抽帧 |
| Canvas 呈现 | 无（Chat 区显示执行进度） |

### 4.3 异常结果 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 将检测结果结构化呈现，供用户批量审核、删除误检、修改分类 |
| 输入 | 异常事件集合（来自异常查找 Sub-Agent） |
| 输出 | 经人工审核后的确认事件集合（删除了误检、修正了分类的最终结果） |
| 决策逻辑 | 根据任务类型决定卡片展示字段：市容环卫 → 细分类（生活垃圾/满溢/建筑垃圾）；车辆违停 → 增加车牌号字段；城市异常 → 支持按事件类型筛选 |
| 可调用 Skill | OCR（车牌识别）、地址反解析（街道名称）、卡片渲染 |
| Canvas 呈现 | 批量卡片（截图+检测框+街道+时间戳+细分类），支持删除和修改 |

### 4.4 智能派单 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 根据确认事件的类型和位置，自动匹配接收方，供用户调整确认 |
| 输入 | 确认事件集合 + 后端"区域 x 事件类型 → 接收方"映射表 |
| 输出 | 派单结果集合（每条事件对应一个接收方），已发送的派单通知 |
| 决策逻辑 | 查映射表自动匹配；若某事件无法匹配到接收方（映射缺失），标记为"待手动指派"提示用户 |
| 可调用 Skill | 派单映射查询、通知推送 |
| Canvas 呈现 | 派单结果列表（事件 <-> 接收方），支持手动调整对应关系 |

### 4.5 数据检索 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 从历史数据库中按条件检索已有事件记录 |
| 输入 | 查询条件（时间范围 + 空间范围 + 事件类型筛选） |
| 输出 | 符合条件的历史事件记录集合 |
| 决策逻辑 | 根据查询条件复杂度决定：简单查询 → 直接数据库检索 Skill；复杂查询（如"问题最多的三条路"）→ 先检索再聚合统计 |
| 可调用 Skill | 数据库检索、数据聚合统计 |
| Canvas 呈现 | 无（Chat 区显示检索进度） |

### 4.6 报告生成 Sub-Agent

| 项目 | 说明 |
|------|------|
| 职责 | 汇总上游数据，生成多维度可视化报告 |
| 输入 | 事件数据集（来自异常结果或数据检索）+ 派单数据（如有） |
| 输出 | 结构化报告（含图表和地图），支持导出 |
| 决策逻辑 | 根据输入来源决定报告模板：来自实时检测任务 → 包含派单详情+派单地图+事件分布+接收方排名；来自历史检索 → 包含趋势分析+类型对比+空间热力图+接收方统计 |
| 可调用 Skill | 报告模板渲染、统计图表生成、地图热力图渲染 |
| Canvas 呈现 | 完整报告页面，可导出 |

## 5. Agent-Skill 能力清单

MVP 所需最小 Skill 集，随 See 智能体和 Sub-Agent 扩展可持续新增。

| # | Skill 名称 | 能力描述 | 被哪些 Sub-Agent 调用 |
|---|-----------|---------|---------------------|
| 1 | 地址解析 | 将自然语言地名转为地理围栏坐标 | 查询范围确定 |
| 2 | 摄像头匹配 | 根据地理围栏查询范围内的摄像头列表及覆盖范围 | 查询范围确定 |
| 3 | 地图渲染 | 在 Canvas 区渲染地图，标注摄像头、事件点、热力图等 | 查询范围确定、报告生成 |
| 4 | 摄像头抽帧 | 从摄像头视频流中按策略抽取帧画面 | 异常查找 |
| 5 | 特征-分割识别 | 单帧/少量帧目标检测（垃圾、违停车辆、乱停非机动车等） | 异常查找 |
| 6 | 连续帧时序判断 | 多帧序列+时间窗口行为推理（店外经营、游商小贩等） | 异常查找 |
| 7 | OCR | 识别车牌号、招牌文字等 | 异常结果 |
| 8 | 地址反解析 | 根据摄像头坐标反查街道名称 | 异常结果 |
| 9 | 卡片渲染 | 在 Canvas 区渲染批量审核卡片 | 异常结果 |
| 10 | 派单映射查询 | 查询后端"区域 x 事件类型 → 接收方"映射表 | 智能派单 |
| 11 | 通知推送 | 向接收方发送派单通知（短信/系统消息） | 智能派单 |
| 12 | 数据库检索 | 按条件查询历史事件记录 | 数据检索 |
| 13 | 数据聚合统计 | 对检索结果进行分组、排序、Top-N 等聚合运算 | 数据检索 |
| 14 | 统计图表生成 | 生成饼图、柱状图、趋势图等可视化图表 | 报告生成 |
| 15 | 报告模板渲染 | 按模板组装完整报告页面 | 报告生成 |

## 6. 非功能性需求

MVP 阶段功能和效果优先，性能指标在功能跑通后根据实际情况补充。以下为必须满足的约束：

| 维度 | MVP 要求 |
|------|---------|
| 数据安全 | 视频流数据不落盘、不出域，仅存检测结果和截图 |
| 部署方式 | 支持私有化部署 |
| 权限控制 | MVP 单角色，预留多角色权限框架 |
